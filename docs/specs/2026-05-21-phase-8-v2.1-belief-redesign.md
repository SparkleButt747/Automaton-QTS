# Phase 8 v2.1 — News-Belief Mechanic + Dispatch Causality Redesign

**Status:** Approved (design grilled 2026-05-21, see `.grill/phase-8-v2.1-belief-redesign.md`)
**Supersedes mechanic in:** `docs/specs/2026-05-21-phase-8-news-reactive-strategy.md` (v2)
**Author context:** money-making algo-trading system, not academic.

---

## 1. Goal

Make the correctly-decoded news signal actually reach the strategy and evolve
**causally** through the trading day, so `NewsReactiveMomentum` produces non-zero
trades on the real 2023-12-13 FOMC dataset. Tuning it to beat buy-and-hold is
explicitly **out of scope** (that is the deferred Optuna grill's job).

## 2. Background — the v2 bug (do not re-litigate the rest)

First real v2 run (Qwen3.6-35B-A3B Q6 via llama.cpp, real 2023-12-13 FOMC data)
proved the LLM decodes Powell's dovish pivot correctly: net bullish, 11 bull /
2 bear / 12 neutral across 25 events. Yet the strategy made **0 trades**. Three
coupled defects:

1. **`BeliefAxis.update()` REPLACES** the scalar. The presser is 25 events in ~90
   min; the final event (#25, a procedural Q&A) classified neutral (alpha 0.0),
   wiping the whole dovish signal to zero. `news_alpha_at()` returned 0.0 at every
   bar.
2. **`run_real_backtest` pre-dispatches ALL text events before the bar stream**, so
   the belief is frozen at the last event's value for the whole day — no causal
   evolution. Worse, `BeliefAxis.at()` **amplifies** for bars before `last_update`
   (negative elapsed → `0.5 ** negative > 1`): a latent look-ahead bug, masked here
   only because the final belief was 0.
3. **`news_signal_weight` (0.5) × peak single-event alpha (~0.26) = 0.13**, below the
   0.25 entry threshold. Defaults too weak even with a non-zero belief.

**Confirmed solid — DO NOT touch:** `LlamaCppClient`, the classifier prompt/quality,
the content-hash disk cache (warmed for 2023-12-13, ~25 entries, gitignored), and the
overall classify→belief→strategy→backtest plumbing.

## 3. Design

### 3.1 `NewsBelief` — multi-axis decaying accumulator

Replaces `BeliefAxis` in `src/qts/strategies/belief.py`. Three independently-decaying
accumulators, combined at read time per the rule **relevance gates, confidence drives,
magnitude scales**.

**State** (all `init=False`): `_conviction: float = 0.0`, `_relevance: float = 0.0`,
`_magnitude: float = 0.0`, `_last_update: datetime | None = None`. Config:
`half_life: timedelta` (shared across axes).

**Decay helper** (the look-ahead guard lives here):

```python
def _decay(self, now: datetime) -> float:
    if self._last_update is None:
        return 1.0
    elapsed = max(0.0, (now - self._last_update).total_seconds())  # GUARD: never negative
    hl = self.half_life.total_seconds()
    if hl <= 0:
        return 1.0
    return 0.5 ** (elapsed / hl)
```

**`observe(signal: NewsSignal, now: datetime) -> None`** — decay conviction, then fold;
relevance/magnitude are **running-max** (peak seen), no time decay:

```python
d = self._decay(now)
self._conviction = self._conviction * d + signal.direction_sign * signal.confidence
self._relevance = max(self._relevance, signal.relevance)   # running-MAX: low-rel can't lower it
self._magnitude = max(self._magnitude, signal.magnitude)   # running-MAX
self._last_update = now
```

**`value_at(now: datetime) -> float`** — pure read (no mutation); **only conviction decays**:

```python
if self._last_update is None:
    return 0.0
d = self._decay(now)
return (self._conviction * d) * self._relevance * self._magnitude
```

**Properties of this design:**
- **Accumulates:** a burst of same-direction confident reads builds `_conviction`
  beyond a single event (fixes defect #1). The final neutral Q&A adds
  `0 × confidence = 0` to conviction and (being low-relevance) cannot lower the
  relevance gate → **ignored, not cancelling.**
- **Causal & guarded:** `value_at` is pure and `_decay` clamps negative elapsed to 0
  (fixes the amplification half of defect #2). Belief is exactly `0.0` before the
  first `observe` → naturally causal.
- **`_conviction` is unbounded** (it accumulates), so `value_at` is **no longer
  bounded to [-1, 1]** the way `NewsSignal.alpha_contribution()` was. This is
  intentional: accumulated conviction is what lets the blended alpha clear the
  entry threshold (fixes defect #3). The blend weight + Optuna handle scaling. See
  §7 "Decisions to confirm" — flag if you'd prefer a `tanh` squash.
- **Single, intuitive decay:** only `_conviction` decays, so a lone event's belief
  halves in exactly one `half_life` — `half_life` means what Optuna expects it to.
  Conviction decay is the *only* forgetting mechanism (one mechanism, not three).
- **Running-max gates:** `_relevance`/`_magnitude` track the *peak* seen, not a
  decayed "recent" value — they never independently close, so they can't double-decay
  the belief. Within a single FOMC day peak ≈ recent, and conviction decay handles
  forgetting. (A future multi-day grill may revisit whether the gates should decay
  across days — out of scope here.)

`BeliefAxis` is fully replaced (its only consumer is `NewsReactiveMomentum`). Remove it.

### 3.2 Causality via Nautilus-native custom data

Text events become a Nautilus custom data type so the **engine interleaves them with
bars by timestamp** — events for `ts ≤ T` are delivered before bar `T`. This solves the
ordering bug at the engine level with no hand-maintained pending list (fixes defect #2).

**`NewsDataPoint`** — new Nautilus `Data` subclass (`src/qts/nautilus/news_data.py`)
carrying the **raw** text (classification happens on receipt, mirroring live trading):

- Fields: `source: str`, `persona: str | None`, `text: str`, plus Nautilus-required
  `ts_event: int` and `ts_init: int` (nanoseconds).
- The implementer confirms the exact 1.221 mechanism (subclass
  `nautilus_trader.core.data.Data` with `ts_event`/`ts_init` properties, or the
  `@customdataclass` decorator).

**Converters** (add to `src/qts/nautilus/converters.py`, mirroring `nautilus_bar_to_qts`):
- `text_event_to_news_data(event: TextEvent) -> NewsDataPoint` —
  `ts = int(event.timestamp.timestamp() * 1e9)`.
- `news_data_to_text_event(data: NewsDataPoint) -> TextEvent` — reconstruct, recovering
  `timestamp` from ns via `datetime.fromtimestamp(ns / 1e9, tz=UTC)`. (Timestamp-rounding
  is irrelevant to cache lookup — the cache key is `sha256(source ‖ text ‖ version)`,
  timestamp-free — so `classify()` still hits cache after the roundtrip.)

### 3.3 Actor wiring (`src/qts/nautilus/actor.py`)

- **`on_start`:** after `subscribe_bars(...)`, also
  `self.subscribe_data(DataType(NewsDataPoint))`. Always subscribing is harmless when no
  news data is present (non-news strategies just never get a callback).
- **`on_data(self, data) -> None`:** the generic Nautilus custom-data handler.
  ```python
  if isinstance(data, NewsDataPoint):
      event = news_data_to_text_event(data)
      try:
          self._inner_strategy.on_text(event)
      except Exception:  # noqa: BLE001 — cache miss raises KeyError; log and continue
          logger.exception("on_text failed for news event from %s", data.source)
  ```
  (Guard required: `NewsClassifier.classify()` raises `KeyError` on cache miss.)
- **Remove `on_text_event`** (the manual method). It was only ever called by
  `run_real_backtest`'s pre-dispatch, which §3.4 deletes. Grep for callers
  (`grep -rn "on_text_event"`) and update/remove them, including any unit tests.

### 3.4 Runner wiring

- **`run_terrain_backtest`** (`src/qts/nautilus/runner.py`): add optional
  `custom_data: list | None = None`. After `engine.add_data(nautilus_bars)`:
  ```python
  if custom_data:
      engine.add_data(custom_data)   # engine merges + sorts all data by ts_init
  ```
- **`run_real_backtest`** (`src/qts/nautilus/real_runner.py`): **delete the pre-dispatch
  loop** (lines 48-53). Instead build news data and thread it through:
  ```python
  news_points = [text_event_to_news_data(e) for e in episode.text_events]
  return run_terrain_backtest(episode.terrain, strategy, ...,
                              custom_data=news_points)
  ```
  Update the module docstring (it currently documents the pre-dispatch approximation as
  "fine for v2" — that approximation is now gone).

### 3.5 Strategy (`src/qts/strategies/news_reactive.py`)

- Swap `BeliefAxis` → `NewsBelief`; `on_text` becomes:
  `signal = self._classifier.classify(event); self._belief.observe(signal, event.timestamp)`.
- `news_alpha_at(now)` → `return self._belief.value_at(now)`.
- `on_bar` blend is **unchanged**: `blended = (1-w)*combined_alpha + w*news_alpha`.
- **Add a belief trajectory recorder** (supports the acceptance test's causality check
  and the future dashboard): in `on_bar`, append `(bar.timestamp, news_alpha)` to
  `self._trajectory: list[tuple[datetime, float]]`; expose read-only via a
  `belief_trajectory` property.

## 6. Testing strategy

**Unit — `NewsBelief`** (`tests/unit/test_belief.py`, IDs `T-V21-BELIEF-*`):
- Accumulation: two same-direction bull `observe`s at the same instant →
  `value_at` strictly greater than one alone.
- **Ignored-not-cancelling:** a strong bull `observe`, then a `neutral`
  (relevance≈0) `observe` → belief stays positive (the neutral did not wipe it).
  This is the regression test for defect #1.
- Decaying-max gate: a high-relevance read then a low-relevance read → relevance gate
  reflects the high read (decayed by time), not the low one.
- Decay: after a single `observe`, `value_at(t0 + half_life)` is exactly half of
  `value_at(t0)` (only conviction decays, so halving is exact).
- **Guard:** `value_at(t)` for `t < last_update` never exceeds `value_at(last_update)`
  (no amplification). Regression test for the negative-elapsed bug.
- Empty: `value_at` before any `observe` is `0.0`.

**Unit — converters** (`T-V21-CONV-*`): `text_event_to_news_data` →
`news_data_to_text_event` roundtrip preserves `source`/`persona`/`text` and the cache
key is unchanged.

**Unit — actor** (`T-V21-ACTOR-*`): `on_data` with a `NewsDataPoint` forwards a
reconstructed `TextEvent` to the inner strategy's `on_text`; a classifier `KeyError` is
caught (no exception escapes `on_data`).

**Integration** (`T-V2-ACCEPT`): §4.

All runs use `.venv/bin/python -m pytest --no-cov -q`.

## 7. Decisions to confirm (raised by this spec)

- **Unbounded conviction.** `value_at` can exceed [-1, 1] by design (§3.1). If you'd
  rather keep news_alpha bounded (compose more predictably with the blend weight), say
  so and I'll wrap conviction in `tanh`. Default in this spec: **no squash** (simpler;
  Optuna's weight scales it).
- **Always-subscribe to `NewsDataPoint`** in the shared actor vs gating behind a config
  flag. Default: **always** (harmless, no flag — YAGNI).

## 8. Custom-data path — VERIFIED (Nautilus 1.221 spike, 2026-05-21)

The one real risk (no existing custom-data usage in the repo) was de-risked with a live
BacktestEngine spike. Confirmed working pattern — the plan carries this exact code:

1. **`news_data.py` must NOT use `from __future__ import annotations`.** `@customdataclass`
   introspects real type objects via `__annotations__`; stringized annotations crash it.
   ```python
   from nautilus_trader.core.data import Data
   from nautilus_trader.model.custom import customdataclass

   @customdataclass
   class NewsDataPoint(Data):
       source: str = ""
       persona: str = ""
       text: str = ""
   # ts_event / ts_init are added by the decorator (ns-int kwargs at construction).
   ```
2. **Wrap + add with a `client_id`** (raw `Data` subclasses are NOT routed — only
   `CustomData` wrappers are):
   ```python
   from nautilus_trader.model.data import CustomData, DataType
   from nautilus_trader.model.identifiers import ClientId
   dt = DataType(NewsDataPoint)
   wrapped = [CustomData(data_type=dt, data=p) for p in news_points]
   engine.add_data(wrapped, client_id=ClientId("QTS_NEWS"))  # client_id REQUIRED for custom data
   ```
3. **Actor:** `self.subscribe_data(DataType(NewsDataPoint))` in `on_start`; `on_data(self, data)`
   receives the **raw `NewsDataPoint`** (the engine publishes `CustomData.data`, not the wrapper).
4. **Verified behaviours:** events interleave correctly by `ts_init` (bar, bar, news, bar,
   bar, news, bar); always-subscribing is harmless on vanilla no-news runs (0 callbacks, no
   errors). The spec's earlier "manual per-bar drain" fallback is therefore **not needed**.
